# AI 味检测 · 语料基线校准 交付说明

> 把 AI 味检测的判定基准，从「我拍脑袋设的通用值」换成「作者本人 715 章真实语料的分位数」。

---

## 一、核心变化：判据语义被重新定义

原来每个维度的判据是 `scale(实测值, 人写参考值, AI参考值)`——语义是「**像不像 AI**」。

**但语料全是人写的，它无法告诉我们 AI 长什么样。** 所以校准不是换数字，而是改语义：

```
判据从「像不像 AI」→「离你自己的正常写作范围有多远」

span = p95 − p05
high-bad（越高越像 AI）: d = max(0, (v − p95) / span)     ← 边界取上侧
low-bad （越低越像 AI）: d = max(0, (p05 − v) / span)     ← 边界取下侧
score = round(clamp01(d / 1.0) × 100)

值落在正常带内 → 0 分；偏离达「一整个正常带宽度」→ 100 分
```

**这解决了三个问题**：
1. **诚实**——不假装我们知道 AI 文本长什么样（语料里确实没有 AI 样本）
2. **规避误判**——这正是朱雀调研预警的头号风险（网文天然套路化，用通用基线会冤枉人）
3. **契合定位**——「写作体检」本来就是看「偏离你的常态多少」

## 三、零膨胀指标：从密度口径改为计数口径

`connector_per1000` 与 `parallel_per100sent` 在语料里 **p95 = 0**（715 章里分别只有 1 章 / 8 章非零）——这是**人写口语化网文的事实**，不是数据错。

若走主公式，`span = 0` → 除零 → **任意一个「然而」把该维度打到 100 分**。

### 最终判据（计数口径，长度无关）

```
score = round(clamp01(count / (3 × max(corpusMaxCount, 1))) × 100)

connector: corpusMaxCount=1 → denom=3  →  1次=33, 3次=100
parallel:  corpusMaxCount=2 → denom=6  →  1次=17, 2次=33, 6次=100
```

**为什么是计数而非密度**（这是本轮最关键的一次证伪）：

| 文本长度 | 1 个「然而」在密度口径下 | 计数口径 |
|---:|---:|---:|
| 600 字 | **100 分** | 33 分 |
| 1127 字 | 62 分 | 33 分 |
| 1967 字 | 36 分 | 33 分 |
| 2807 字 | 25 分 | 33 分 |

密度是**长度相关量**——同一个词在短章里密度更高 → 被过度惩罚。计数口径长度无关，也与 UI 文案「约 3 次/章才算显著」一致。

**结构性保证**：因 `KZ=3 > 1`，`corpusMaxCount / denomCount ≡ 1/3` → **作者自己最极端的那一章也只有 33 分**，不可能因自身风格被重判。

### 两个 corpusMaxCount 的由来（已反推验证）

| 指标 | 密度最大章 | 整数反推 | 非零章数 |
|---|---|---|---|
| connector | `0.470 @ 2124 字` | `1000/2124 = 0.4708` → **1** | 1 / 715 |
| parallel | `1.850 @ 108 句` | `200/108 = 1.852` → **2** | 8 / 715 |

⚠️ 注意：**不能用「最大密度 × 中位章节长度」折算**——那两个数来自**不同的章**。密度是 `count × 单位 / 长度`，整数反推才精确。

## 五、本轮修掉的问题（全部由测试或 QA 发现）

| # | 问题 | 性质 |
|---|---|---|
| 1 | **段落节奏误判人写文本 92 分** | 网文对白场景一两句一段，段落长度天然整齐，用散文基线会冤枉人。改为「段落中位 <120 字时该维度不参与判定」→ 后续重设计为 `para_cv` 低向判据 |
| 2 | 注释写「不计为问题」但分数仍 92 | 分数与结论矛盾，是坏味道 |
| 3 | `嘴角勾起`→`笑了一下` 产生病句 | 违反「本地规则瞎改比不改更糟」原则，删掉此类 replace 规则 |
| 4 | 「不仅」被当连接词删掉 | 「不仅仅是」→「是」，裸「不仅」在正常中文里太常见，改为只检测成对结构 |
| 5 | **破折号判据是死代码** | `dash_ellipsis_per1000` 不是任何维度主指标 → 反查落进兜底 → 破折号子信号恒 0 分。改用显式 `METRIC_JUDGE` 表 |
| 6 | `isBaselineStale()` 假警报 | 只改打分不改特征提取时误报「基线过期」，会让用户学会忽略这个提示。新增独立 `FLAVOR_FEATURE_VERSION` |
| 7 | 对白墙护栏 `skipped=false` | 会把该维度当「评估过、没问题」计入总评、拉低总分。语义应是「不适用」→ 改 `skipped=true` |
| 8 | 旧口径基线静默兜底 | 缺 `corpusMaxCount` 时按 denom=3 静默判分（parallel 会算错）。改为 unjudged + 披露 |
| 9 | 零膨胀密度口径长度依赖 | 600 字章节 1 个连接词得 100 分。改计数口径 |
| 10 | parallel 贪婪正则计数低估 | 紧邻结构被合并 → 6 处只数到 3。10 条正则全部改惰性 |
| 11 | `corpusMaxCount === null` 漏判 | `undefined` 判断漏过 `null` → 静默按新口径判分。改 `== null` |
| 12 | 基线非单调时静默饱和 100 分 | `p05 > p95` → span=ε → 任意值满分。加护栏 → unjudged + 披露 |
| 13 | **测试用例数不确定** | vitest 缓存残留引用已删探针 → 偶现 15/269。加 `cache: false` 使每轮从零收集 |
